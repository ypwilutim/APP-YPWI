# Fix SK File Access - All Assignments Can Access Their Own SKs

## Problem Analysis

**Current Issues:**
1. **Non-privileged users:** Only checks `assignments[0].teacher_id` (first assignment only)
2. **Privileged operators (SDM, admin, etc.):** Skips teacher_id check entirely, only validates tenant via `verifyTenantAccess`
3. **Result:** Users with multiple assignments can't access SKs from other assignments; privileged users can access ANY SK in their tenant

## Desired Behavior

**ALL users (privileged or not) can access SKs where `sk.teacher_id` matches ANY of their assigned `teacher_id`s from assignments.**

- If user has assignments: can access SKs for ANY of their assigned teacher_ids
- If user has no assignments but has `guru_id`: fallback to `guru_id`
- Tenant access still validated for cross-tenant security

## Implementation Plan

### 1. Add Helper Function in `src/routes/sk-guru.js` (or `src/middleware/auth.js`)

```javascript
// Get all teacher_ids user has access to via assignments
function getUserTeacherIds(user) {
  const ids = new Set();
  if (user.guru_id) ids.add(user.guru_id);
  if (user.assignments) {
    user.assignments.forEach(a => {
      if (a.teacher_id) ids.add(a.teacher_id);
    });
  }
  return Array.from(ids);
}
```

### 2. Update `/file/:skId` Endpoint in `src/routes/sk-guru.js` (lines 757-764)

Replace current logic with unified check:

```javascript
// Get all teacher_ids user has access to
const userTeacherIds = getUserTeacherIds(req.user);

if (!userTeacherIds.length) {
  return res.status(400).json({ success: false, message: 'Teacher ID tidak ditemukan di token' });
}

// Check if SK belongs to one of user's assigned teachers
if (!userTeacherIds.includes(sk.teacher_id)) {
  return res.status(403).json({ success: false, message: 'Akses ditolak untuk SK ini' });
}

// Still validate tenant access for cross-tenant security
if (!verifyTenantAccess(req, sk.tenant_id)) {
  return res.status(403).json({ success: false, message: 'Akses ditolak untuk tenant ini' });
}
```
