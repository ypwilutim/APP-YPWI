# ADMQU Page Implementation Plan

## Overview
Create a new self-service page `public/admqu.html` accessible via direct button on `dashboard.html` for all authenticated roles. The page contains three tabs: SK Guru, Ringkasan Absensi, Slip Gaji - each showing individual data for the logged-in user.

---

## Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **Page Location** | `public/admqu.html` | Separate page, clean separation from existing dashboards |
| **Access Model** | Self-service (individual data only) | User requirement: "di akses secara individu" |
| **Absensi Scope** | Individual monthly summary | Personal attendance stats: hadir/izin/sakit/terlambat |
| **Slip Gaji Source** | Existing treasurer APIs | Reuse `/treasurer/public/salary-slip/:teacherId/:month` and history |
| **Button Visibility** | All authenticated users | Universal access from dashboard.html |

---

## API Endpoints Required

### Existing (Reuse)
| Endpoint | Purpose |
|----------|---------|
| `GET /api/sk-guru/teachers/:id/data` | Teacher data for SK preview |
| `GET /api/sk-guru/list?tenant_id=X` | List existing SKs for user's tenant |
| `GET /api/sk-guru/file/:skId?format=pdf` | Download SK (PDF/DOCX) |
| `POST /api/sk-guru/generate` | Generate new SK |
| `GET /api/admin/attendance-monthly?tenant_id=X&bulan=M&tahun=Y` | Monthly attendance (will filter by teacher_id) |
| `GET /treasurer/public/salary-slip/:teacherId/:month` | Individual slip gaji PDF |
| `GET /treasurer/public/send-salary-slip-email` | Email slip (optional) |

### New API Endpoints
| Endpoint | Description |
|----------|-------------|
| `GET /api/admqu/sk-status` | Check if user has SK for current hijri year; return existing SK or eligibility |
| `GET /api/admqu/absensi-ringkasan?bulan=M&tahun=Y` | Individual attendance summary for logged-in teacher |
| `GET /api/admqu/slip-gaji?bulan=M&tahun=Y` | Individual slip gaji data (salary components + attendance deductions) |
| `GET /api/admqu/slip-gaji/history` | List previously generated slip periods |

## Backend Implementation

### 1. New Route File: `src/routes/admqu.js`
```javascript
const express = require('express');
const db = require('../../db');
const { authenticateOperator } = require('../middleware/auth');

const router = express.Router();

// GET /api/admqu/sk-status - Check SK for current hijri year
router.get('/sk-status', authenticateOperator, async (req, res) => {
  // 1. Get logged-in user's teacher_id from token/assignments
  // 2. Check sk_guru table for records where teacher_id = user's teacher 
  //    AND hijri_year = current hijri year
  // 3. Return { hasSk: boolean, skData: {...}, eligible: boolean }
});

// GET /api/admqu/absensi-ringkasan?bulan=M&tahun=Y
router.get('/absensi-ringkasan', authenticateOperator, async (req, res) => {
  // 1. Get teacher_id from logged-in user
  // 2. Query attendance_logs + leave_requests for that teacher in given month
  // 3. Return counts: hadir, izin, sakit, terlambat, dinas_luar, cuti, tanpa_keterangan
});

// GET /api/admqu/slip-gaji?bulan=M&tahun=Y
router.get('/slip-gaji', authenticateOperator, async (req, res) => {
  // 1. Get teacher_id from logged-in user
  // 2. Fetch salary components from teachers/temp_teachers
  // 3. Calculate attendance deductions using existing payroll logic
  // 4. Return breakdown + total
});

// GET /api/admqu/slip-gaji/history
router.get('/slip-gaji/history', authenticateOperator, async (req, res) => {
  // List previously generated slip periods from payroll history
});
```

### 2. Register Route in `server.js`
```javascript
const admquRoutes = require('./src/routes/admqu');
app.use('/api/admqu', admquRoutes);
```

## SK Guru Flow (Self-Service)

### States
1. **Has SK for current hijri year** → Show existing SK with Download (PDF/DOCX)
2. **No SK for current hijri year** → Show "Ajukan SK Baru" form
   - Form fields: jenis SK (baru/kembali/tetap/kontrak/honorer), custom tgl_mulai/tgl_selesai, PT, TMT
   - Preview button (calls `/api/sk-guru/preview`)
   - Submit button (calls `/api/sk-guru/generate`)

## Edge Cases & Considerations

| Scenario | Handling |
|----------|----------|
| User has no teacher_id in token | Redirect to login / show error |
| User has multiple assignments | Use primary assignment (first) |
| No SK template for tenant | Show message, disable generate |
| Payroll not configured for tenant | Show salary components as 0, allow view |
| Hijri year calculation mismatch | Use server-side hijri year from SK module |
